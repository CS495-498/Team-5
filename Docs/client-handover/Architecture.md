## Overview

OED follows a standard client-server architecture, with a backend service responsible for business logic and data access, and a database layer for persistent storage.

## Components

#### **Application Server**

The backend handles:

* API routing  
* Authentication and authorization  
* Business logic execution  
* Input validation

Security improvements were implemented directly within this layer, including validation, rate limiting, and access control enforcement.

#### **Database**

PostgreSQL is used for persistent storage of application data, including users and energy metrics.  
Changes were made to improve configuration security and eliminate unsafe practices such as hardcoded credentials.

#### **Authentication & Session Management**

Authentication is handled at the application level.  
Enhancements include:

* Migration to HTTP-only cookies for session storage  
* Improved session expiration handling  
* Mitigation of user enumeration risks

#### **Logging and Monitoring**

A structured logging pipeline is used to capture application activity.  
Logs are generated by the application and forwarded for aggregation and visualization. These logs support debugging, monitoring, and detection of abnormal behavior.

#### **CI/CD Pipeline**

Automated testing is integrated into the development workflow. All changes are validated through tests before being merged.

## Architectural Notes

The overall system design remains unchanged. Improvements were made by introducing security controls across existing components rather than adding new services.
